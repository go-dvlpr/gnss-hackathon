# Competitor Feature Matrix & MVP Scoping

Твоє завдання — дослідити вказаних конкурентів, побудувати об'єктивну матрицю функціоналу та допомогти сформувати реалістичний MVP-скоуп для продукту користувача.

## Крок 1. Збір даних про конкурентів
Для кожного конкурента знайди актуальну інформацію (офіційні сайти, сторінки тарифів, документацію, відгуки):
1. Основне позиціонування та цільова аудиторія.
2. Повний перелік функцій (Core features, інтеграції, аналітика, автоматизація, мобільні версії тощо).
3. Монетизація та обмеження на базових/безкоштовних тарифах.
4. Головні скарги користувачів (чого не вистачає у відгуках).

*Важливо: спирайся лише на підтверджені факти з відкритих джерел або наданих користувачем файлів. Якщо даних щодо конкретної фічі немає — став позначку `❓ Невідомо`.*

## Крок 2. Побудова матриці фічей (Feature Matrix)
Згрупуй усі знайдені функції за логічними категоріями (наприклад: Онбординг, Основний воркфлоу, Інтеграції, Командна робота, ШІ-функції).

Створи Markdown-таблицю такого формату:

| Категорія | Фіча / Можливість | Конкурент А | Конкурент Б | Конкурент В | Статус для ринку |
| :--- | :--- | :---: | :---: | :---: | :--- |
| Core | Назва фічі 1 | ✅ | ✅ | ✅ | Table stakes (база) |
| Core | Назва фічі 2 | ✅ | ❌ | ⚠️ (обмежено) | Диференціатор |

Використовуй позначки:
- `✅` — повноцінно реалізовано
- `⚠️` — реалізовано частково або лише в дорогих тарифах
- `❌` — відсутнє
- `❓` — немає публічної інформації

## Крок 3. Gap-аналіз (Прогалини ринку)
Після таблиці виділи три короткі блоки:
- **Обов'язковий мінімум (Table Stakes):** фічі, які є у 80%+ конкурентів. Без них продукт не сприйматимуть серйозно.
- **Сліпі зони конкурентів (White Space):** корисні функції, яких немає ні в кого або вони реалізовані погано (потенційні точки диференціації).
- **Перевантажений функціонал (Bloatware):** складні фічі конкурентів, які рідко потрібні на старті.

## Крок 4. Рекомендації щодо MVP-скоупу
Сформуй конкретний план першої версії продукту у вигляді трьох списків:
1. **Must-have (Входить в MVP):** базовий мінімум + 1–2 сильні фічі-диференціатори для швидкого виходу на ринок.
2. **Nice-to-have (Реліз v1.1):** фічі, які варто додати одразу після перших продажів.
3. **Out of scope (Відкласти):** усе, що затримає запуск без критичної цінності для перших користувачів.
